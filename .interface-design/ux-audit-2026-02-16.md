Four simulated user personas evaluated the Arithmusic UI cold. Personas: bedroom music producer (22, Ableton user), math undergrad (20, Fourier analysis background), casual non-technical user (35, marketing), creative coder / generative artist (30, Max/MSP & SuperCollider).

## Critical (every user hit these)

### 1. "What is x?" — universal confusion
Every persona was confused about what `x` means in `f(x)`. The domain toggle hints at it but never states it. The equation field has zero inline context. This is the single highest-impact gap because `f(x)` is the entire premise of the app.

### 2. No equation cheat sheet or syntax hints
Nobody knows what functions are available (`sin`, `cos`, `pi`?), whether to use `^` or `**`, or what a valid expression looks like. The equation input is a blank box with no affordance for discovery. The musician asked "can I type D4 instead of 293.66?" The math student wondered about `π` vs `pi`. The casual user didn't know they could type anything beyond a number.

### 3. Graph has no legend linking colors to tracks
Three colored traces, three tracks — but nothing connects them visually. Users infer the relationship from the LED dots eventually, but it takes time and guessing.

---

## High Priority (multiple users, clear friction)

### 4. Wave type selector has zero click affordance
The sine wave icon on each track row reads as a label, not a button. Three users questioned whether it was interactive. The collapsed single-icon state doesn't look clickable.

### 5. Timeline chips are uniform width regardless of segment duration
A 100ms segment and a 3000ms segment look identical. The "timeline" is really just an ordered list. Proportional width would make it an actual timeline and help users understand the temporal structure at a glance.

### 6. "Infini-Slide" label communicates nothing
Charming branding, but every user flagged it as confusing. The math student wanted to test its limits; the casual user ignored it; the musician thought it was a joke.

### 7. Volume 0–200% is unexplained
Why 200? Does it clip? Overdrive? No visual feedback for clipping. The `0 — 200` caption under the slider reads as a range label, not an explanation.

---

## Medium Priority (specific personas, real but survivable)

### 8. Output field feels redundant when valid
When the expression is correct, it just echoes back `f(x) = 110`. Showing the note name for constant-frequency expressions (e.g., "A2") would connect the math world to the music world. The power user suggested showing `f'(x)` for rate of change. At minimum, show the closest note name.

### 9. No segment boundary markers on the graph
Can't see where one segment ends and the next begins on the traces. The graph shows continuous curves per track with no visual division.

### 10. BEAT domain toggle does nothing
It's component-local state with no dispatch. Toggles visually, zero effect on synthesis or graph. Either implement or remove to avoid misleading users.

### 11. No keyboard shortcuts
No spacebar for play/pause, no arrow keys for segment navigation, no Ctrl+Z on expressions. Every interaction requires mouse.

### 12. "New Tab" as a default segment name
Multiple users flagged this as looking like a browser glitch or accidental naming. (This is from the initial-state demo composition.)

---

## Lower Priority / Feature Requests (power user)

### 13. No amplitude envelopes per segment
Every segment is hard-on/hard-off rectangular window → click transients at boundaries. Even 8ms linear fade-in/fade-out would eliminate clicks.

### 14. Wave type is per-track, not per-segment
Can't do sine glide → sawtooth stab on the same track. Forces users to create extra tracks for timbral variation.

### 15. Volume as static percentage, not a function
Can't express amplitude envelopes via math. If volume were also `g(x)`, the tool jumps from "draw frequencies" to "draw frequencies and envelopes."

### 16. No stereo / panning
Mono output only (`createBuffer(1, ...)`). Can't pan tracks.

### 17. The `multiplier` setting is mysterious
It scales `x` globally but has no explanation. Conflates "tempo" (musical) with "expression time scale" (mathematical).

### 18. No cross-segment continuity for x
Each segment resets `x = 0`. If segment 1 ends at `f(2.5)` and segment 2 starts, `x` jumps back to 0. Phase carries forward but expression variable doesn't.

### 19. No spectrogram mode
Current graph shows `f(x)` the expression, not actual spectral content of the audio. A spectrogram would be more musically informative.

### 20. Graph is not interactive
Can't click to seek playback, hover to see frequency at cursor, or zoom into regions.

### 21. No per-segment preview / audition
Play always synthesizes entire composition. No "audition this segment" button. Must mute other tracks manually.

### 22. No looping per track
Can't make a 3-segment bass line repeat for the full composition duration.

### 23. Timeline needs zoom
With many segments, horizontal scrolling is required and chips get tiny. Timeline zoom should be tied to graph X axis.

---

## What's Working Well (power user noted)

- Graph playhead with phosphor glow layers is genuinely good
- Dim vs. highlighted track traces when a segment is selected
- Color threading (green/amber/blue/red) across graph, LEDs, editor dot, accent strip
- Drag-to-insert from template tray is the best single interaction
- `ValidatedField<T>` architecture — every field carries its own error state
- JSON save/load — no backend, composable, version-controllable
- WASM → JS fallback is solid defensive engineering
- The TI-92 calculator aesthetic is distinctive and well-executed
